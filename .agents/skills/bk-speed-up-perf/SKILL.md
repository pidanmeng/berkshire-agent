# 加速 Berkshire Agent

把「让它更快」转成可复现的用户路径测量与有证据的小修复。这是指引，不是配额或脚本：广撒网、跟随已测量成本、拒绝不为用户实际跑的工作负载带来改进的诱人改动。**状态：** 当前可实测面只有 `apps/berkshire-agent` 前端骨架；计划的性能关键路径（tick 流 → Rust → Tauri event → webview zustand → ECharts、DuckDB 热缓存、批量/定节奏扇出）仍是目标态（[architecture.md §2](../../../docs/architecture.md#2-运行时拓扑)、[architecture.md §4](../../../docs/architecture.md#4-端到端数据流主路径)），其测量/基准设施标注「待实现」，不得臆造基准命令当已存在。

## 确立范围与当前权威

读 [AGENTS.md](../../../AGENTS.md)、[docs/architecture.md](../../../docs/architecture.md)（拓扑/数据流）、[docs/data-model.md](../../../docs/data-model.md)（缓存失效链、单写者）、[docs/plugin-development.md](../../../docs/plugin-development.md)。用 [bk-ci-test-reliability](../bk-ci-test-reliability/SKILL.md) 处理过程/时钟/浏览器/异步清理。

对齐用户可见端点、工作负载范围、资源约束、可接受的小行为差异、停止条件。**后端与浏览器端到端测量分开**：快的迭代器/fold 不证明快的传输/绘制/滚动/输入响应。

## 调查用户路径，再给候选定级

需要广度时委派独立域，要求测量与生产调用点而非猜测：

- 应用冷启动、首次历史读取、当前 generation 重开。
- 长会话、大消息/结果、多次导航。
- 首屏可用绘制、旧页加载、滚动、inactive-view 激活。
- 实时流与重连。

区分独立成本驱动：字节、持久事件、压缩记录、行数、工具数、子项、可见 DOM 节点是不同量级。不要只丢「大量相同小消息」就叫真实负载——先检查它在压哪个用户操作。

按可观测用户延迟、CPU/分配、保留内存、发生频率、置信度给候选定级。为每个命名生产消费者、重复工作、预期复杂度、最小可证伪干预、必须保持稳定的行为。可疑循环/未用缓存/大文件本身不是瓶颈证据。

## 先建可复现基准

目前只在真实骨架面建基准：
- `apps/berkshire-agent` 前端：冷启动到首帧、路由切换、图表初始渲染可用 `bun run build` + 手动/脚本测量（无正式基准设施，标待实现）。
- **不用用户私有数据**：构造固定、经评审的常量输入；不复制 prompts/路径/身份/Id/凭据/录屏到夹具或产物。基准不依赖用户 home、环境仓库、网络服务或私密数据。

计划中的关键面（tick 流/热缓存/侧车调度）**暂无运行码可测**——测量它们需先落地对应能力（待实现）。在此之前，把「优化目标」记录为 `TODO` 或 PR 讨论，不假装已测量。

## 证明回归，再移除工作

在改生产代码前跑未优化工作负载，保存命令/版本/运行平台/夹具尺寸/原始测量/判定。把失败场景缩到仍打中真实瓶颈，再在打补丁前给可证伪假设定级。用 profile、分配样本、工作计数或阶段计时区分它们。

常见模式（可测、非自动处方）：
- 让紧凑表示经下游读取保持紧凑；避免读侧消费已结算内容或单个聚合时逐行建对象。
- 在识别真实归属/信任转换后再去重复解析/复制/freeze/校验。类型化同进程借用不是弱化耐久或 wire 解析的许可。
- 分离只读准备与写/发布工作，不把 awaited 工作移过正确性必到端点。
- 后移 inactive-view/折叠细节工作；延迟不是删除。
- 稳定身份、收窄订阅，使单个变化节点不至于令整段历史失效；保持更新顺序与即时事件。
- 用合适数据结构替代反复 shift/scan/重建；测整个消费者路径而非孤立的容器运算。
- 用 key-版本复用/singleflight 时需显式失效、有界保留、独立等待者取消、处置归属带入。

一次改一个因果因子；重跑聚焦场景与其端到端父路径。要求负控制：收紧的断言在原实现或受控重引入目标成本时失败。预算到放得下回归就不是保护；预算低于已验证噪声底也不可靠。**BK 红线：** 优化绝不能违反缓存失效链（先建新快照再原子替换，禁止「写文件却返回旧对象」——[data-model.md §5](../../../docs/data-model.md#5-缓存分层与失效链)），也不得绕过单写者（[data-model.md §1](../../../docs/data-model.md#1-核心设计决策)）。

## 保护行为与资源归属

性能测量是功能证据的补充，不是替代。为输出/顺序/分页/流索引/错误/取消/并发/处置按适用跑或加窄隶属测试；保留模型-可见/已记录等价、原子发布、必需校验、可写就绪。不要为凑数字而静默截断历史、跳过工具结果、关不变量或改生命周期语义。任何有意的细微可见差异标注并经其隶属证据复核。

当优化收益端到端消失、典型负载实质回归、复杂度胜过小收益、或取消/保留/耐久无法解释与测试时，拒绝之。简短记录被拒假设而不扩范围去证明它。

## 交付受界、可审的结果

KB 当前无基准/测试车道，交付形态为：`bun run build` 可复现测量 + PR 说明（负载 → before/after → 端点与内存语义 → 行为证据 → 负控制 → 确切检查 → 排除项）+ `TODO`/讨论记录计划面的优化目标。推送前用 [bk-pre-push-checks](../bk-pre-push-checks/SKILL.md) 选最小证据。分开作者自报历史数、新鲜本地测量与 CI 证据；停在议定场景/修复范围，把排序后的跟进清单留下而别追无关机会。
