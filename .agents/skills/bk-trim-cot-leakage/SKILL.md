# 精简「推理过程泄漏」

推理过程泄漏的文案，其视角是**撰写会话**而非仓库：引用只有那次会话能看到的产物、叙述改动而非状态、或在与已离开的审查者争辩。**修复绝不只是删除**——当一段文字带着事实分句时，把每个事实按 `HEAD` 重述，再删其周围的会话记录；一段不携带任何事实分句时（如审计代号、控制流叙述）直接删。**必需背景：** 命题保留规则归 [bk-prose-standard](../bk-prose-standard/SKILL.md)；本仓库特有的诚实纪律（不得把 docs 目标态当已实现）归 [AGENTS.md](../../../AGENTS.md) 与 [secondary-development.md](../../../docs/secondary-development.md)。

## 唯一检验

对每处可疑文字问：**一个只读 `HEAD`、接触不到任何会话转写/PR 线程/未提交草稿的读者，能否解析每个引用并核实每个声明？** 不能，就把存活事实从仓库视角重述、删其余；能，则不是泄漏（无论听起来多像历史）——但在当前状态面上（README/docs/JSDoc），一段可解析的改动故事仍是改动叙述，路由到其许可之家（决策记录或 TODO 标记）。

## 分类法

1. **悬空的设计会话引用**——`(决策 7)`、`(审计 C2)`、`设计 §4.7`、`计划 §1.4`、阶段标签（`T4`、`W3`、`P-I`）、"设计台账"、"(B 裁定)"。若决策有已提交的 owner，按名与路径引用它；否则删该引用并把其事实分句重述为独立成立。
2. **改动与版本痕迹**——"used to"、"no longer"、"旧的 X"、指标性戳（"v1"、"这一版"、"今天"、"现在"对比过去态）。陈述当前行为；已修复的回归写成现在时的反事实（"没有 X 就发生 Y"），绝不写仓库史（"曾经 Y"）。
3. **审查编排**——"Review 里被拒："、"reviewer 确认了"、草稿序数（"本注 v5"）、轮次归属。保留存活的决策与理由为平实事实；删谁何时说的。
4. **面向审查者自证的辩护**——"这个 cast 是安全的，它只是…"、"这是对的因为…"。一个自证自己正确性的注释是在对话审查者而非维护者。陈述使代码安全的不变量，或若代码已能看出就删注释。
5. **控制流叙述与推导记录**——"我们先 X 再 Y"、测试走查、明显分支的证明。删；只留非显然契约或不变量。
6. **犹豫与规划残留**——"现在大概没问题"、"应该够了"、无标记的延后。升级为 `TODO`/`FIXME` 或重述为实际边界；删犹豫。
7. **目标态当已实现的声张（本项目特有红线）**——把 `docs/` 目标态能力（`ctx.*`、`@berkshire/cordis`、`packages/`、DuckDB 写者）写成"已存在"/示例可直接 import。按 [AGENTS.md](../../../AGENTS.md) 重述为「目标态/尚未实现」。

## 什么不是泄漏

- **Issue/PR 编号与 TODO(name):** 在 `HEAD` 可解析；任何面都保留，包括 README。
- **反事实回归钉**："没有 X 就发生 Y"、"朴素 X 会…"。
- **测量边界**：校准常量的"（测量：512 巢 ≈ 0.15s）"，证据词"measured/测量"是承重的。
- **运行时新旧态**："旧连接排空后新连接才 accept"是运行时生命周期，不是改动史。
- **项目口吻与文体**："我们"作项目口吻；决策记录的备选-考虑过段。
- **显式标注的「目标态示例」**：若某段已标为设计演示且读者不会误以为可运行，属许可范围内（但仍需 clear 标注）。

## 工作流

1. 按 [bk-prose-standard](../bk-prose-standard/SKILL.md) 确认 scope（显式范围；`vendor/` 与未来的 `notes/archived/` 不动）。
2. 先只审计：读范围内最密的文案（模块 JSDoc、README、docs 页）手上不带正则，再用 `rg` 找分类法引脚（计数 1~7 的模式），并逐一语义判定——探针不是定义，认真读。
3. 修复 owner-first：模型/用户可见字符串 → 按 bk-prose-standard 复现；文档 → 改 owner 源再重链；目标态声张 → 按 AGENTS.md 改成诚实表述。
4. 删前列举段落命题（prose-standard），并查过度修正陷阱：把义务翻成背书、把假设抬成已发货功能、删真事实、或丢掉证据源。
5. 验证：重跑引脚，只允许「合规保留 + 本技能目录 + owner 引用的证据」；确认每个残留引用在 `HEAD` 可解析；对触及面跑对应门禁（文档 → 链接/术语一致性；骨架代码 → `bun run build`）。

## 过度修正陷阱

- 把"必须"义务杀成"可以"背书；
- 把未发货设计抬成"已发货功能"；
- 删除真事实或证据来源；
- 把「目标态」说成「已实现」反向泄漏。
