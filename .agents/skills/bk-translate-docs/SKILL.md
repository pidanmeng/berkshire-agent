# Berkshire Agent 文档翻译（待实现）

> **⚠ 状态：待实现。** 本仓库当前是**中文为主的单语体**：`docs/` 全中文、无语言切换器、无 `foo.md ↔ foo.zh.md` 配对、无一致性校验脚本、无 `.i18n.yaml`。因此本技能描述的**完整双语流程当前不可运行**（没有设施、没有门禁可跑）。此处保留的是「若未来引入中英对照」应遵循的工作流与取舍说明，供决策参考——**不要把它当成当前可用能力**（诚实见 [AGENTS.md](../../../AGENTS.md)、[secondary-development.md](../../../docs/secondary-development.md)）。

## 取舍说明

- **项目已选择中文为主**：目标受众是国内投研/AI 开发者，`docker`/CLI 英文输出不在本项目范围。**默认不做中英对照**。
- 引入双语**唯一理由**应是：面向国际用户发布、或需与上游英文参考/审计文档（如 `docs/reference/cordis-pattern-report.md`、`cordis-methodology.md`）做可持续对照。此时才需建设配对设施。

## 若要引入双语：必须物（先建设施，再翻译）

在开始任何翻译前，仓库必须先具备（**当前均不存在，属待建**）：

1. **配对命名约定与切换器**：`foo.md`（英文）↔ `foo.zh.md`（中文）+ 每篇 `foo.i18n.yaml`（记录两侧一致性哈希）；H1 后放 `[English](foo.md) | 中文` 切换行。
2. **一致性校验脚本**：校验行数/标题层级/表格行列/代码围栏/链接端点/术语（对应 dsh 的 `verify-translation-pairing`——BK 内以 `scripts/` 里的 bun 脚本形态出现，见 [AGENTS.md 命令节](../../../AGENTS.md#命令bun-版) 的「待实现」）。
3. **术语表**：`docs/i18n/terminology.md`，本仓库术语（能力缝、三角色、dispatch/@mode、profile/bundle/patch、单写者、fail-closed、复权/PIT/交易日等）双向绑定。

## 若设施已就绪：翻译流程

**核心基调（承接 dsh）：本技能是工作流地图，不是翻译记忆。** 双语两侧等权；任一语言都可能作为某次更新的源语。

### 按改动类型分流

- **更新**（配对已存在、一侧被改）：最小化改配对另一侧，保存未改动部分的既有经审措辞；**绝不整篇重译**（重译会丢已审措辞）。对改动的 Markdown 单元（段落/表格行/列表项/标题）逐句核对源语——无增减、术语照表、代码围栏逐字保留。
- **新建配对**：整体翻译。先读术语表，再逐节翻译、每节结构锁死源语。
- **删除/改名文档**：连同其 `.i18n.yaml` 一起删/改，否则配对门禁报不完整配对。

### 翻译准则

- **写，不要字对字转**。读一个语义单元，再用母语技术作者的语域重述；保留必需框架，不强求逐句对应。
- **第二遍逐句核对源语**：保真在此核对，而非写时靠直觉——确认无增加/无遗漏、每术语照表、代码跨逐字存活。
- **脱离源语通读译文**：很多拗口只在孤立阅读时显形；重写该句而非往里补词。
- **术语严格**：本仓库术语表中每条渲染完全按表；未收录且无出处的新术语，要么提供可引用的中英文先例，要么保留英文并标「待定术语」，绝不临时臆造翻译。
